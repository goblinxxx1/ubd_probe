# Семантичний relevance-суддя для екстракції оферів (local LLM, $0)

**Дата:** 2026-08-24
**Статус:** затверджено (brainstorm), експериментальний («давай пробувати, можливо спрацює»)
**Скоуп:** краулер — додатковий семантичний гейт над екстракцією. Backend не чіпаємо.

## Проблема (корінь, не прояв)

Екстрактор — евристика («мішок термінів» у межах блоку): офер-тригер / знижка / аудиторія можуть збігтись **семантично непов'язані**. Роками латається вузькими гейтами, але клас відкрито-кінцевий. Живі прояви:
- **412** — сторінка завантаження музики, пісня названа «Допоможе **ЗСУ**», «**безкоштовно** mp3» → хибний офер «безкоштовно для військових». «ЗСУ» — назва пісні, не бенефіціар.
- **Vidviay 408** — сторінка «Публічна оферта» (терми), розділ «6. Знижки» витягнуто як офер.
- (**White Clinic 407** — сайт-банер «10% для УБД» на сторінці імплантів; це переважно ДЕДУП-проблема, див. «Межі».)

Спільне ядро (412, терми) — **семантичне**: «чи це справді вигода ДЛЯ нашої аудиторії, чи слова просто збіглися». Регекс це не закриє надійно (research: на цьому евристика плато, потрібна семантика).

## Рішення: локальний LLM-суддя як ДОДАТКОВИЙ шар (не заміна)

Гібрид (research-backed: дешеві правила = recall, LLM = precision лише на low-confidence): чинна евристика лишається **повністю**; суддя робить фінальну семантичну перевірку кандидатів, що інакше пішли б у модерацію.

**Рушій:** Qwen2.5-7B-Instruct (Apache-2.0, безкоштовні ваги) через `llama.cpp` (`llama-server`), локально в Docker → **$0 API назавжди**. Обсяг — десятки кандидатів/день + кеш → латентність/CPU неважливі.

### Інваріант надійності (ключовий)
**Суддя — strictly additive. Ручні гейти НЕ прибираємо.**
- Ручні гейти лишаються базовою точністю (нуль залежностей, = сьогодні).
- Суддя ловить лише семантичний залишок, який гейти пропускають (клас 412).
- **Qwen недоступний (тимчасово АБО назавжди) → система = рівно сьогодні.** Нуль регресії. Суддя — чистий плюс; його втрата = втрата лише додаткових відсівів.

### Деградація + самолікування
- Виклик судді щопроходу з коротким таймаутом. Недоступний → кандидат іде в модерацію **як сьогодні**, краулер рушає далі. Пайплайн ніколи не блокується.
- **Кеш вердиктів по `content_hash`** (persistent, /data): стабільність (вбиває фліп-флоп Vidviay), нуль повторних викликів. Qwen повернувся → нові + cache-miss ре-краули судяться автоматично.
- **Circuit-breaker:** якщо виклик впав — пропускаємо суддю до кінця ЦЬОГО проходу (легкий backoff), не б'ємо мертвий сайдкар на кожному кандидаті.

## Компоненти

- **`Judge` (protocol, нове):** `verdict(candidate) -> Verdict{genuine: bool, page_scoped: bool, reason: str}`. `genuine` = реальна знижка/безкоштовна вигода САМЕ цій аудиторії (закриває 412/терми). `page_scoped` = ця знижка — промо САМЕ ЦІЄЇ сторінки, а не сайт-широкий банер, випадковий на цій сторінці (закриває White Clinic: на сторінці імплантів «10% УБД» = банер → `page_scoped=false`; на присвяченій сторінці знижки → `true`). Pluggable — реалізації взаємозамінні за конфігом (llama.cpp зараз; Haiku-свап у майбутньому — один рядок).
- **`LlamaCppJudge` (нове):** HTTP-клієнт до `llama-server` (OpenAI-сумісний `/v1/chat/completions` або нативний `/completion`), httpx з таймаутом. GBNF-граматика → гарантовано валідний JSON `{genuine, reason}`. Компактний укр-промпт + few-shot із реальних кейсів (412/терми — негативи; published — позитиви). Низька температура (детермінізм).
- **`VerdictCache` (нове):** JSON на /data, ключ `content_hash` → `{genuine, reason, ts}`. Persist після кожного нового вердикту.
- **`RelevanceGate` (нове):** обгортка з кешем + circuit-breaker + деградацією. `keep(candidate) -> bool`. Викликається в екстракт→submit шляху.
- **Інтеграція:** у `_process_page` (і активний `ActiveHarvester._process_page`, і пасивний `Runner._process_page`) — після `extract()` дав кандидата, ПЕРЕД додаванням у submit-набір: `if not gate.keep(cand): continue`. `keep()` = `genuine AND page_scoped`. Два call-site, один компонент.
- **`NullGate`/disabled:** якщо `JUDGE_ENABLED=false` або URL порожній → `keep()==True` завжди (= сьогодні). Дефолт поведінки при будь-якій відсутності судді.

## Docker-сайдкар (автономність)

- Новий compose-сервіс `llama` (`profiles: ["crawler"]`): образ із `llama-server`, Qwen2.5-7B-Instruct Q4_K_M GGUF (~5ГБ) у **persistent-волюмі** (завантажується раз, пін-URL+SHA; healthcheck на `/health`).
- Краулер: `JUDGE_URL=http://llama:8080`, `depends_on: llama (service_healthy)` — але з **деградацією**, тож навіть якщо llama не підніметься, entrypoint краулера працює.
- `docker compose --profile crawler up -d` → усе саме, вічно, нуль ручних кроків.
- RAM: ~5-6ГБ (є ~12ГБ вільно в Docker-VM). CPU-інференс повільний, але обсяг мізерний → байдуже.

## Промпт (суть)

Система: «Ти — модератор знижок для військових/ветеранів/УБД тощо. Дай вердикт по ДВОХ вимірах: (1) `genuine` — чи текст пропонує РЕАЛЬНУ знижку/безкоштовну вигоду САМЕ ЦІЙ аудиторії, чи аудиторне слово/знижка просто випадково згадані (назва пісні/новина/умови-договору/чуже); (2) `page_scoped` — чи ця знижка є промо САМЕ цієї сторінки, чи це сайт-широкий банер, випадковий на сторінці з іншим змістом». Few-shot: 412 (пісня «ЗСУ» → genuine=false), терм-пункт (→genuine=false), «10% УБД»-банер на сторінці про імпланти (→genuine=true, page_scoped=false), реальна присвячена «знижка 15% для ветеранів» (→genuine=true, page_scoped=true). Вхід: title+body+discount+audience+url кандидата. Вихід (GBNF): `{"genuine": bool, "page_scoped": bool, "reason": "<коротко укр>"}`.

## Конфіг

`judge_enabled` (env `JUDGE_ENABLED`, дефолт true), `judge_url` (`JUDGE_URL`), `judge_model`, `judge_timeout_seconds` (дефолт ~30), `judge_cache_path` (/data/judge_cache.json). Усе — звичайні ручки; `judge_enabled=false` = миттєвий відкат на сьогодні.

## Тестування (verify-by-execution — критично для «можливо спрацює»)

- **Юніт (fake Judge, детерміновано):** junk-кандидат відкинуто; genuine лишено; суддя-unavailable → лишено (деградація, нуль регресії); cache-hit пропускає виклик; circuit-breaker після падіння.
- **Жива валідація (окремий харнес):** прогнати РЕАЛЬНИЙ Qwen на: 412, Vidviay-408-текст, White-Clinic-407-текст + вибірка з БД (N published = мають лишитись, M rejected = мають відсіятись). Виміряти precision/recall судді. **Це і є перевірка «спрацює чи ні»** — рішення тримати/тюнити приймаємо на цих числах.
- **Жива Docker:** сайдкар піднімається, healthcheck; краулер судить реальний прохід; вимкнути llama → краулер деградує на сьогодні без падіння.

## Межі (чесно)

- **Закриває (ціль треку):** релевантність-клас — 412 (випадковий збіг слів), терм-сторінки (Vidviay), off-topic згадки; + **White Clinic** через `page_scoped` (банер-на-чужій-сторінці → suppress). Усі три живі кейси — у скоупі.
- **Ризик `page_scoped` (валідувати):** сайт, де знижка ЛИШЕ в банері й нема присвяченої сторінки → `page_scoped=false` скрізь → офер втратиться. Для White Clinic не проблема (є присвячена сторінка 124), але харнес живої валідації МУСИТЬ це виміряти на вибірці, щоб `page_scoped` не різав легітимні banner-only офери. Якщо ріже — лишаємо лише `genuine`, а White-Clinic-дедуп на backend-трек.
- **Ручні гейти лишаються всі** (інваріант надійності). Жодної «консолідації-видалення» цим треком.

## Поза скоупом (YAGNI)

Backend-дедуп (site-banner, shadow-gate) — окремо. Haiku/хмарний рушій — свап за конфігом пізніше. Ретрейн/навчений класифікатор — відкинуто (ML-тягар).
