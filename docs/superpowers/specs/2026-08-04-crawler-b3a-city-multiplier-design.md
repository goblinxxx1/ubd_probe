# B3a — Місто як матеріалізований множник гріда (crawler)

**Дата:** 2026-08-04
**Гілка:** `feat/crawler-b3a-city-multiplier` (від `main`, HEAD 7f962da)
**Тип:** crawler-only. Backend/admin не змінюються.
**Контекст:** Трек B, фаза B3 (пошуковий оверхол). B1 (revisit-cooldown 21д) і B2
(блок-партиція DDG↔searxng + свап) уже влиті/задеплоєні. Батьківський дизайн:
`2026-08-04-crawler-search-overhaul-design.md` §3a. Пам'ять
[[ubd-crawler-news-exclusion]], [[ubd-crawler-city-axis]].

## Проблема
Поточна місто-вісь (`CityAxis`, `city_axis.py`) — **діагональна розгортка** по
**повному газетиру** (~1229 назв): одне місто/прохід суфіксується на зріз фраз,
простір (місто×фраза) не матеріалізується. Активна в проді
(`city_axis_enabled=True`, `city_queries_per_pass=10`). Наслідки: місто-таргетинг
розмазаний і некерований; малі містечка палять бюджет; ротація непередбачувана
для блок-партиції/due-walking.

## Рішення — матеріалізований множник по курованих містах
Місто стає **справжнім множником** по **курованому** списку ~45 найбільших/обл-
центрів. `build_grid` матеріалізує фіксований простір ~1701 фраза; наявна блок-
партиція/свап (B2) ротує по ньому без окремого місто-механізму.

### Арифметика (чому саме так)
- База (незмінна): `INTENT_FORMS`(13) × `AUDIENCE_FORMS`(27) = **351**.
- Гео-зріз: `GEO_INTENTS`(5) × `GEO_AUDIENCES`(6) = **30** base-фраз, які отримують
  місто-суфікс.
- Гео-блок: 30 × `GRID_CITIES`(45) = **1350**.
- **Разом = 351 + 1350 = 1701.** Без дублів: «знижка ветерани» (плоска, у 351) ≠
  «знижка ветерани Київ» (гео).
- Стеля ~1700 навмисна: §4 батьк-специфікації — пропускна ~180 фраз/добу (DDG сам),
  повний обхід ~7-9 днів ≈ `SEARCH_CACHE_TTL_HOURS=168`. Множення всіх 351×45≈15800
  обходилося б ~88 днів → фрази протухали б задовго до ревізиту (ламає freshness).
  Тому місто множить **курований зріз 30**, а не всі 351.

### Куровані таблиці (у `query_grid.py`, поряд з наявними осями)

`GRID_CITIES` (45; окуповані виключено):
- **Обл-центри під контролем уряду (22):** Київ, Харків, Одеса, Дніпро, Львів,
  Запоріжжя, Вінниця, Полтава, Чернігів, Черкаси, Житомир, Суми, Хмельницький,
  Чернівці, Рівне, Тернопіль, Івано-Франківськ, Луцьк, Ужгород, Кропивницький,
  Миколаїв, Херсон.
- **Найбільші не-центри (23):** Кривий Ріг, Кременчук, Біла Церква, Кам'янське,
  Умань, Бровари, Бориспіль, Ірпінь, Буча, Нікополь, Павлоград, Олександрія,
  Ковель, Калуш, Дрогобич, Червоноград, Мукачево, Бердичів, Ніжин, Конотоп,
  Шостка, Ізмаїл, Краматорськ.
- **Виключено (окуповані, немає живих мерчант-оферів):** Донецьк, Луганськ,
  Сімферополь, Севастополь, Маріуполь, Мелітополь, Бердянськ.

`GEO_INTENTS` (5) ⊆ `INTENT_FORMS`: `знижка`, `акція`, `безкоштовно`,
`спеціальна пропозиція`, `пільгова ціна`.

`GEO_AUDIENCES` (6) ⊆ `AUDIENCE_FORMS`: `військові`, `ветерани`, `УБД`,
`учасники бойових дій`, `ветерани війни`, `мобілізовані`.

Форми — у наявному **називному** відмінку (як увесь `build_grid`: «знижка
ветерани»); пошуковики стійкі до відмінка, окрема давальна таблиця = зайва
складність (YAGNI).

### `build_grid` — матеріалізація й порядок
- Сигнатура: `build_grid(cities: list[str] | None = None) -> list[str]`.
  `None` → `GRID_CITIES`; `[]` → лише база 351 (rollback / OFF). DI для тестів.
- **Порядок:**
  1. Наявні **351** тим самим порядком (intent-major, audience-minor) → перші 351
     **байт-ідентичні** сьогоднішнім (мінімум churn для `block_cursor`).
  2. Далі гео-блок вкладеним порядком **intent → audience → city** (місто —
     внутрішнє): «знижка військові Київ», «знижка військові Харків», … → сусідні
     фрази блока різняться містом (гео-різноманіття в межах 15-блоку).
- Dedup case-insensitive (як зараз). Стабільний детермінований вихід.

### Виведення діагонального `CityAxis` з експлуатації (superseded=dead)
Матеріалізація робить діагональ надлишковою й небезпечною (подвоєння міст, якщо
лишити активною поверх: «знижка ветерани Львів Одеса»). Це **не** «degraded≠dead»
із [[feedback-preserve-working-structure]] — механізм свідомо витісняється кращим.
**Чисте видалення:**
- `SearchPass.__init__`: прибрати `city_axis`, `city_queries_per_pass`; тіло `run`
  — прибрати `city_on`-гілку (лінії 27-28, 37-40, 51-53).
- `SearchState`: прибрати `city_cursor` (+ `set_city_cursor`).
- `wiring.py`: прибрати імпорт/інстанс `CityAxis` і передачу city-params.
- `config.py`: прибрати `city_axis_enabled`, `city_queries_per_pass` (обидва місця
  дефолтів + `from_settings`).
- Файл `city_axis.py` **видалити** (не лишати осиротілим — щоб не вводити в оману);
  разом із `tests/test_city_axis.py`.

**Названий компроміс:** малі містечка зникають із **ЗАПИТІВ** (лишаються куровані
45). Але `geo.py` **екстракція** досі впізнає всі ~1229 назв у завантажених
сторінках → гео-тегування оферів **не** звужується. Звужується лише таргетинг
запитів — саме мета B3a.

### Rollback-прапор
`config.grid_cities_enabled: bool = True` (заміна знятому `city_axis_enabled`).
- `True` → `build_grid()` з `GRID_CITIES` (1701).
- `False` → wiring кличе `build_grid(cities=[])` → лише 351 (сьогоднішня база без
  діагоналі). OFF-простір = чистий 351.

## Обсяг / файли
- `query_grid.py` — `GRID_CITIES`/`GEO_INTENTS`/`GEO_AUDIENCES`, новий `build_grid`.
- `search_pass.py` — прибрати city-params/гілку.
- `search_state.py` — прибрати `city_cursor`.
- `wiring.py` — прибрати CityAxis; прапор `grid_cities_enabled`.
- `config.py` — знятий city_axis*, доданий `grid_cities_enabled`.
- **Видалити:** `city_axis.py`, `tests/test_city_axis.py`.

## Тести (TDD, спершу червоні)
- `build_grid`: розмір = 1701; перші 351 == сьогоднішній `build_grid` (байт-стабільний
  префікс); гео-блок присутній і в порядку intent→audience→city; dedup; `cities=[]`
  → 351; DI малим списком міст дає передбачуваний розмір/порядок.
- `GRID_CITIES`: 45 унікальних; окуповані відсутні.
- `SearchPass`: працює без city-params (сигнатура оновлена; наявні блок-партиція/
  свап-тести лишаються зелені).
- `SearchState`: без `city_cursor` (серіалізація/round-trip оновлені).
- `config`/`wiring`: `grid_cities_enabled` (True→1701, False→351); `city_axis*`
  знято.

## Деплой
Канонічний ребілд crawler після merge. Env: `GRID_CITIES_ENABLED=1` (дефолт).
Жива верифікація: грід=1701, у запитах з'являються «{intent} {audience} {місто}»
по курованих містах, діагональ зникла, throttle не зріс (простір фіксований).
