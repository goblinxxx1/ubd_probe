# Рунбук: перезапуск краулера з новим кодом

**Для кого:** людина, що просто виконує команди в терміналі. Програмувати не треба.
**Коли:** після того, як у код краулера (папка `crawler/`) або в налаштування пошуку внесли зміни і їх треба «викотити» на живий стек.

Кожен крок — це команда, яку треба **скопіювати цілком** і вставити в термінал, натиснути Enter, дочекатися завершення, і лише тоді переходити до наступного.

---

## 0. Що потрібно перед початком

1. **Docker Desktop має бути запущений.** Відкрий програму «Docker Desktop», зачекай, поки кит-іконка внизу перестане блимати (статус «Engine running»).
2. **Відкрий термінал у папці проєкту.** Найпростіше:
   - Відкрий папку `D:\ubd_probe` у Провіднику Windows.
   - У порожньому місці натисни правою кнопкою миші → **«Відкрити в терміналі»** (або «Open in Terminal»).
   - Має відкритися чорне/синє вікно, де останній рядок закінчується на `D:\ubd_probe>`.

> Якщо термінал відкрився в іншій папці — введи команду `cd D:\ubd_probe` і натисни Enter.

Усі команди нижче виконуються саме в цьому вікні.

---

## 1. Зберегти код на сервер GitHub (пуш)

Це відправляє локальні зміни в хмару, щоб вони не загубилися.

```bash
git push origin main
```

**Що маєш побачити:** рядок на кшталт `8c30491..b7d4b39  main -> main`.
**Якщо написало `Everything up-to-date`** — усе вже збережено, це нормально, йди далі.

---

## 2. Зібрати новий образ краулера «з нуля»

Це найдовший крок (може тривати кілька хвилин). `--no-cache` означає «зібрати повністю заново, нічого не брати зі старих запасів» — так гарантовано потрапить свіжий код.

```bash
docker compose --profile crawler build --no-cache crawler
```

**Що маєш побачити наприкінці:** рядок `Image ubd_probe-crawler Built` (або схожий, зі словом `Built`).
**Поки йде:** багато технічних рядків — це нормально, чекай.

---

## 3. Перезапустити краулер і пошуковий сервіс

Це вимикає старі контейнери і піднімає нові — уже з новим образом. `--force-recreate` = «навіть якщо здається, що нічого не змінилось, все одно пересоздай».

```bash
docker compose --profile crawler up -d --force-recreate crawler searxng
```

**Що маєш побачити наприкінці:** рядки `Container ubd_probe-crawler-1  Started` і `Container ubd_probe-searxng-1  Started`.

---

## 3.5. Сервіс `llama` (суддя релевантності) — читай один раз

Краулер має «розумного помічника» — сервіс `llama` (локальна LLM Qwen2.5-7B), який відсіює нерелевантні знахідки. Кілька важливих фактів:

- **Його НЕ треба перезбирати** (крок 2 його не стосується). Це готовий образ із інтернету, а не наш код.
- **Він має просто бути піднятий.** Перевір:

  ```bash
  docker compose ps llama
  ```

  Якщо в колонці статусу `Up ... (healthy)` — усе гаразд, нічого робити не треба.
  Якщо його взагалі немає у списку або написано `Exited` — підніми його разом з рештою:

  ```bash
  docker compose --profile crawler up -d llama
  ```

- **Модель (~4.4 ГБ) завантажується сама** при першому старті й зберігається в Docker-волюмі `ubd-llama-models`. Далі вона НЕ перекачується.
- ⚠️ **Не додавай `llama` у команду кроку 3.** Прапорець `--force-recreate` перезапустив би `llama` даремно, а він при кожному старті ~1 хвилину вантажить модель у памʼять (увесь цей час суддя недоступний). Для викату коду краулера чіпати `llama` не треба.

---

## 4. Перевірити, що все живе

### 4а. Обидва контейнери підняті

```bash
docker compose ps
```

**Що маєш побачити:** у списку є рядки `crawler` і `searxng`, і в колонці статусу написано `Up` (наприклад `Up 5 seconds`).
Якщо навпроти якогось написано `Exited` або `Restarting` — щось пішло не так, дивись розділ «Якщо щось не так».

### 4б. Краулер справді працює (шле пошукові запити)

```bash
docker compose logs --tail=15 crawler
```

**Що маєш побачити:** свіжі рядки з `HTTP/1.1 200 OK` і адресами на кшталт `http://searxng:8080/search?...` або `http://backend:8000/...`. `200 OK` = добре.

### 4в. Суддя релевантності відповідає

```bash
docker compose exec -T crawler python -c "import urllib.request; print(urllib.request.urlopen('http://llama:8080/health', timeout=10).read().decode())"
```

**Що маєш побачити:** `{"status":"ok"}`. Це означає, що краулер бачить суддю і той готовий фільтрувати знахідки.

---

## Готово

Якщо на кроці 4 усе `Up` і в логах є `200 OK` — новий код краулера викочено й працює. Можна закривати термінал.

---

## Якщо щось не так

| Симптом | Що зробити |
|---|---|
| `docker: command not found` або `Cannot connect to the Docker daemon` | Docker Desktop не запущений. Відкрий його, зачекай «Engine running», повтори команду. |
| Крок 1 просить логін/пароль GitHub | Звернись до розробника — треба одноразово налаштувати доступ. Кроки 2–4 можна робити й без кроку 1 (просто зміни не збережуться в хмару). |
| Контейнер `Exited` / `Restarting` на кроці 4а | Виконай `docker compose logs --tail=40 crawler`, скопіюй останні рядки з червоним словом `Error` або `Traceback` і надішли розробнику. |
| Збірка на кроці 2 впала з `error` | Скопіюй останні ~20 рядків виводу і надішли розробнику. Живий стек при цьому не зламався — працює старий образ. |
| Крок 4в не дав `{"status":"ok"}` (помилка/відмова зʼєднання) | Перевір, чи піднятий `llama` (розділ 3.5). Якщо він щойно стартував — зачекай ~1 хв (вантажить модель) і повтори. Якщо `llama` в статусі `Exited` — `docker compose logs --tail=40 llama` і надішли розробнику. |

> **Важливо:** доки крок 2 не завершився словом `Built`, а крок 3 — словом `Started`, старий краулер продовжує працювати. Тобто невдала спроба нічого не ламає — можна спокійно повторити з кроку 2.
